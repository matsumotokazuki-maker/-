# 在庫管理オペレーション基盤 — 運用ガイド

このアプリは「販売計画と在庫計画のズレを早期に検知する」ための意思決定支援ツールです。

設計思想・実装方針の詳細は [`CLAUDE.md`](./CLAUDE.md) を参照してください。
本READMEは**日々の操作手順**に絞ってまとめます。

---

## 🧭 データの流れ（全体像）

```
┌─────────────────────┐
│   業務システム        │ ← 松本君が手動エクスポート
└──────────┬──────────┘
           ↓ (生CSV/xls)
┌─────────────────────┐
│ business_system_export\ │ ← 生ファイルを置く場所
└──────────┬──────────┘
           ↓ convert_raw.bat（変換層）
┌─────────────────────┐
│      input_raw\        │ ← アプリ取込形式
└──────────┬──────────┘
           ↓ update_data.bat（取込）
┌─────────────────────┐
│  data\session_data.pkl │ ← アプリ永続化データ
└──────────┬──────────┘
           ↓ start_app.bat
┌─────────────────────┐
│   ブラウザでアプリ操作   │
└─────────────────────┘
```

### なぜ2段階？

業務システムから出る生データは形式・列構成・エンコーディングがアプリの期待と違うため、**変換層**（`convert_raw_to_app.py`）を挟んで「アプリが食べられる形」に直してから取り込みます。詳細は [`CLAUDE.md` §5.1.3](./CLAUDE.md) を参照。

## 📅 運用サイクル

### 月初・棚卸翌日 — フルロード

棚卸の翌日、業務システムから**7ファイルすべて**を抽出して全置き換えします。

| 抽出対象（生ファイル） | アプリ取込後ファイル |
|---|---|
| 原料データ | 原料データ.csv |
| レシピデータ | レシピデータ.csv |
| 計画数データ | 計画数データ.csv |
| 製造数CSV | 製造数データ.csv |
| 納品予定確認.xls | 納品予定数.csv ＋ 実納品数データ.csv |
| 棚卸データ | 棚卸データ.csv |

### 月中・日次 — 差分追加

毎日、業務システムから**製造数・実納品数**を抽出して追加します。

ファイル名は `YYYYMMDD<種別>.csv` 形式。例：
- `20260507製造数.csv`
- `20260507実納品数.csv`

### 棚卸の修正・追加（C方針：全件上書き）

棚卸は「全期間スナップショット」として扱うため、修正があれば**これまでの全期間の棚卸データ.csv**を再生成して上書きします（差分ではない）。詳細は [`CLAUDE.md` §5.1.2](./CLAUDE.md) を参照。

## ⚡ 日々の操作手順

### A. データ更新（武田が代行可。Claudeに「データ更新お願いします」と依頼）

1. 業務システムから生ファイルを抽出
2. `business_system_export\` に生ファイルを配置
3. **`convert_raw.bat` をダブルクリック** → `input_raw\` に変換済みファイルが出力される
   - 警告ログ（CK振出庫のJAN突合不可など）が出たら内容を確認
4. **`update_data.bat` をダブルクリック** → `data\session_data.pkl` が更新される
   - フルロードか差分追加かは中身から自動判定
5. アプリを再起動して最新データを確認

### B. アプリ起動

`start_app.bat` をダブルクリック → ブラウザが自動で開きます（`http://localhost:8501`）。

終了は黒いコマンドプロンプトで `Ctrl + C`、またはウィンドウを閉じる。

## 🚀 初回セットアップ

### 1. Python（インストール済み確認）

```
python --version
```

`Python 3.9` 以上が表示されればOK。本機は **Python 3.14.4** で確認済み。

### 2. 必要パッケージ

```
pip install streamlit pandas openpyxl
```

本機にインストール済み（pandas 3.0.2 / openpyxl 3.1.5）。

### 3. フォルダ確認

`business_system_export\`、`input_raw\`、`input_processed\`、`data\` の4フォルダが作成されていることを確認。なければ手動で作成。

## 📱 タブレットからアクセス

### 前提

- アプリ起動PCとタブレットが**同じ社内Wi-Fi**にある
- ファイアウォールで**ポート8501**が許可されている

### 手順

1. PCのIPアドレスを確認：`ipconfig` で「IPv4 アドレス」（例：`192.168.1.50`）
2. タブレットのブラウザで `http://192.168.1.50:8501` を開く

## 🛠️ トラブルシューティング

### convert_raw.bat の警告

| 警告内容 | 対応 |
|---|---|
| CK振出庫のJANがレシピに見つからない | 仮JAN（`9992xxxxxxxxx`）で取り込み済み。新商品ならレシピ整備を依頼 |
| 商品名で複数候補ヒット（「（小」と「（小）」など） | 取り込みスキップ。表記揺れを松本君に修正依頼 |
| JAN末尾空白あり | 自動除去済み（情報レベル） |

### update_data.bat のエラー

| エラー | 対応 |
|---|---|
| `フォルダがありません: input_raw` | フォルダを手動作成 |
| `フルロードと差分追加のファイルが混在しています` | どちらか一方だけにする |
| `差分追加するには、先にフルロードを行ってください` | 初回は7ファイルでフルロード |
| `pandas がインストールされていません` | `pip install pandas` |

詳細は [`データ更新バッチの使い方.md`](./データ更新バッチの使い方.md) を参照。

### アプリ起動・接続

| 症状 | 対応 |
|---|---|
| ポート8501が使用中 | `streamlit run inventory_app.py --server.port 8502` で別ポート起動 |
| タブレットから繋がらない | 同一Wi-Fi確認 → ファイアウォール一時無効化で切り分け → 情シスに8501許可依頼 |

## ⚠️ 注意事項

- **社内ネットワーク内利用前提**。インターネット公開不可。
- **単一ユーザー前提**（PoC）。複数人が同じURLで同時編集すると入力が混在する。
- 生ファイルを Excel で開くと JAN が指数表記化／日付フォーマットが崩れるため、**Excelで処理しない**（[`CLAUDE.md` §5.1.1](./CLAUDE.md) データフォーマット契約参照）。
